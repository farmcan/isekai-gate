isekai-live：把喜欢的几秒留成实况

第一版从命令行扩展为浏览器创作室：选视频、截取 1.5/3/5 秒、选帧或自定义封面、裁切比例、长按预览、导出 Live Photo 包及笔记素材。保留 isekai-live 名称，进入创作室，沿用网站杂货铺既有登录保护。

这次改变了什么

原有山谷风格化样片能够说明转换流程，但不太能验证用户为何愿意保存。首版换成已有 MiaoTI 中可辨认的 OIIA 旋转猫与香蕉猫示例，保留来源、加工方式和权利边界，明确它们是经典猫梗，不是实时热榜。用户可直接选择自己从平台保存的视频，不依赖网址解析或账号下载接口。

优先把“挑出最喜欢的几秒”做完整。视频、封面和转码都在浏览器本机处理，不上传媒体，不自动调用收费 AI，不自动发社交笔记。分享层提供 3:4 封面、普通 MP4 和可编辑文案。

实际验证与边界

浏览器实际导出的 3 秒资源包含一致的图片 MakerNote 与 QuickTime 配对标识，Apple PHLivePhoto API 成功读取。另一个实际导出片段为 1.5 秒、360×480，符合 3:4 设置。原有 28 项单元测试通过；这些测试不替代设备验收。工作区旧 Gradio 的 AI 封面参数和下载文件类型问题也已修正。

个人相册实际导入、iPhone 直接保存、动态壁纸及小红书原生实况上传仍待设备实测；普通短视频与 JPG 封面可另行使用。不把浏览器长按预览、配对标识存在或构建成功直接等同于这些兼容性已通过。

为什么复用这些组件

makelive 已实现 Apple 元数据配对；motion-live-photo 提供本机转码工作流参考。本轮复用固定版本 FFmpeg.wasm 与 fflate，保留开源许可。部分同类仓库只生成普通视频与图片，没有真正完成配对，实际源码检查后未将它们的宣传当作已实现能力。

下一步最有价值的验证

先让用户拿自己喜欢的一段视频，走完选段、封面、导出和设备保存，观察是否愿意做第二张。再建立带采集日期、平台原链接和实际传播证据的热门候选清单，验证内容吸引力后再考虑自动选材。当前没有开启定时采集，没有发布小红书笔记，也没有将第三方梗图宣称为原创或免费商用。
